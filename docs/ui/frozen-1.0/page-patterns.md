# WaterX UI 规范 · Page Patterns 1.0

状态：第一轮已确认，作为后续页面迁移与新增页面的结构基线\
依赖：Foundations 1.0、Components 1.0 第一批与第二批\
目标：让新增模块优先复用已经验证的业务页面结构，而不是从空白页面重新拼装。

## 1. 通用规则

- 先识别用户主任务，再选择页面 Pattern；不得只按模块名称决定布局。
- 左侧导航已经明确当前位置时，普通业务页不重复显示大型页面标题、解释文字或版本标签。
- 主工作区优先用于观察和操作；侧栏、说明区、非业务留白不得挤压核心内容。
- 同一个页面只保留一个主任务。次级任务使用 Drawer、Modal 或进入独立页面。
- Pattern 可以替换字段和业务数据，但不得随意改变结构顺序、间距和组件状态。
- 当业务无法归入现有 Pattern 时，应先定义并评审新的 Pattern，不在旧模板内无限增加例外。

## 2. Pattern 01：运营工作台

### 2.1 适用范围

首页、个人工作台、专业模块概览、值班总览。

### 2.2 结构顺序

1. 可选的简短场景标题与时间切换。
2. 4–6 个核心 KPI。
3. 趋势、构成、状态分布等独立内容 Card。
4. 与当前用户或角色相关的任务列表。

### 2.3 约束

- 首页允许保留内容标题，但不重复顶部导航中的系统名称。
- KPI 为态势扫描服务，不把普通详情字段包装成 KPI。
- 静态 KPI 不显示 Hover 或指针反馈；可点击 KPI 必须有完整交互状态。
- 首页图表中的品牌蓝属于信息表达，不等同于业务偏差色。
- 任务区使用普通 Tabs，不使用表格附着型分类页签。

## 3. Pattern 02：数据诊断

### 3.1 适用范围

工艺诊断、水质分析、设备状态对比、能耗分析、多对象数据比较。

### 3.2 结构顺序

1. 扁平筛选工具栏。
2. 紧跟筛选字段的更新、保存等主要操作。
3. 工具栏右侧唯一的页面状态汇总。
4. 一块或多块 Table Surface。

### 3.3 约束

- 工具栏下方不增加分隔线，与首个 Table Surface 保留 8px。
- 两块并列看板默认等宽；左侧外间距、中间距、右侧外间距相等，桌面 16px、紧凑断点 8px。
- 与表格直接关联的数据分类使用 Table-attached Tabs。
- 分类页签、简单表头和简单数据行统一 44px。
- 表头上下横线均为 1px Neutral 100，颜色与粗细一致。
- 数据区纵向滚动时固定表头及其上下横线；滚动条仅出现在表头下方的表体内，并与表头右边缘对齐。
- 页面级正常、预警、告警汇总只出现一次。
- 表头、数据行和末行横线均使用 1px Neutral 100，不加粗末行底线。
- 各页签按自身内容复杂度选择列宽变体：内容可容纳时按业务比例均衡铺满，禁止列内容重叠，也不得制造大面积列间空白。
- 仅当当前页签内容确实放不下时设置内容安全的最小宽度并启用局部横向滚动，不得让短内容页签被同组长内容页签强制滚动。

## 4. Pattern 03：指标评价

### 4.1 适用范围

经济高效、稳定达标、安全运行、合法合规和管理质量评分。

### 4.2 结构顺序

1. 评价周期和总分。
2. 可点击的评价维度卡。
3. 当前维度对应的高级业务表格。
4. 指标详情 Drawer。

### 4.3 约束

- 当前选择使用品牌蓝边框、Neutral 25 背景和 3px 顶部强调线。
- 绿、橙、红只表达评价结果、偏差和风险，不作为当前选择的底色。
- 指标表保留单位、实际值备注和数据状态说明。
- 指标表表头上下横线均为 1px Neutral 100。
- 指标表所有行分隔线和末行底线均为 1px Neutral 100。
- 指标行纵向滚动时固定表头及其上下横线；滚动条从表头下方开始，右边缘与表头对齐。
- 多列表格按业务内容均衡分配列宽；指标列避免无意义过宽，实际值及其备注获得足够空间，单位保持独立且不得被压缩遮挡。内容无法安全容纳时使用局部横向滚动。
- 实际值加粗；复杂数据行使用 60px。
- 操作按钮在空间允许时保持同一行。
- 指标详情使用 Drawer，保留评价表上下文；Drawer 正文只使用一个内容 Surface。

## 5. Pattern 04：主从详情

### 5.1 适用范围

过程评价、检查要点、异常处理、审核、模型诊断和设备详情。

### 5.2 结构顺序

1. 可选的筛选或对象范围工具栏。
2. 左侧对象列表。
3. 右侧当前对象详情及业务操作。

### 5.3 约束

- 左侧列表通常占业务区 28–36%，右侧详情为主工作区。
- 列表和详情之间使用 16px 间距，紧凑断点可使用 8px。
- 当前对象在左侧清晰选中；选择变化只替换详情内容，不整页跳转。
- 右侧详情使用 Flat Group、横向分隔线或必要的单一内容 Surface，避免段落卡片化。
- 不在主从布局内增加第三列固定导航；更深层操作进入 Drawer 或独立页面。

## 6. Pattern 05：业务编辑

### 6.1 适用范围

新增标准、改进措施、异常闭环、审核意见、基础信息维护。

### 6.2 容器选择

- Modal：短确认或少量输入。
- Drawer：需要保留来源上下文的详情与连续填写。
- 独立编辑页：字段多、需要附件、跨区校验或长时间编辑。

### 6.3 约束

- 桌面常规表单采用两列，列间距 16px；长文本和复杂控件跨两列。
- 表单标签、必填、辅助、错误和禁用状态必须完整。
- 操作区保持稳定：取消或次操作在左，保存或提交在右。
- 危险操作使用 Danger 按钮并通过 Modal 二次确认。
- 提交成功后必须给出明确反馈，并说明对象当前状态或下一步。
- 长表单、多层 Tabs 和连续业务流程不得放入 Modal。

## 7. Pattern 选择矩阵

| 用户主任务 | Pattern | 主要组件 |
|---|---|---|
| 快速观察整体状态 | 运营工作台 | KPI、Card、普通 Tabs、任务列表 |
| 筛选并比较多组数据 | 数据诊断 | Filter Toolbar、Table Surface、Table-attached Tabs |
| 从总分下钻到指标 | 指标评价 | Metric Card、Data Table、Drawer |
| 连续选择并处理对象 | 主从详情 | List、Detail Surface、Drawer |
| 创建或闭环业务对象 | 业务编辑 | Form、Modal、Drawer、Feedback |

## 8. Codex / 开发约束

1. 新页面开发前必须在需求或代码说明中标注采用的 Page Pattern。
2. 页面结构顺序应由 Pattern 决定，业务模块不得复制页面后随意重排。
3. Pattern 内所有尺寸、颜色和状态必须继续引用 Foundations Token 与 Components 组件。
4. 不得通过新增 Card 修复对齐问题；优先调整栅格、留白和分隔线。
5. 页面主任务变化时应更换 Pattern，不在原 Pattern 中无限增加条件分支。
6. 每个新页面至少在 1440px 常用工作窗口和 1280px 紧凑窗口完成回归。
7. 页面必须覆盖加载、空数据、错误、无权限和内容溢出状态。
8. 模板确认后，Figma 页面模板与前端实现应使用相同 Pattern 名称和编号。

## 9. 工程基线与后续方式（2026-09-04）

Page Patterns 已确认并进入主产品：

1. 工艺诊断和经济高效基础样式已经抽取为共享 Vue 组件；
2. 首页工作台已经迁移至同一 Token、Button、Card 和 Tabs 基线；
3. 已建立 1280px 与 1440px 首页、工艺诊断、经济高效视觉基线，并补充 1440px 长内容诊断表验证；
4. 当前 Design System 1.0 作为 MVP 的冻结核心基线，后续功能页面按业务优先级渐进迁移，不与业务后端化并行做大规模视觉重构；
5. Figma Variables、组件库和五类页面模板属于设计资产同步工作，可在 MVP 主链路稳定后补齐，不阻塞功能开发；同步时必须沿用现有 Token、组件和 Pattern 名称。
