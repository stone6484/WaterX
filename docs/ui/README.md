## 3. 不再反复讨论的已确认原则

- 专业、克制、清晰、可信。普通业务页以任务和数据为先；驾驶舱另设增强模式，不能反向影响普通页面。
- 深水蓝导航、浅色工作区；深浅场景使用对应 WaterX Logo，橙色 X 不变。不用白色底片承托深色场景的 Logo。
- 固定细线行业图标；一级、二级目录同字号，以场景和字重区分；侧栏保持紧凑，主工作区优先。
- 筛选区扁平、减少重复标题；状态汇总只出现一次。更新 / 保存紧跟日期、靠左；状态靠右。
- 工艺线、日期、筛选与主要操作应共享紧凑工具栏；普通输入/选择控件默认160px、同高，空间足够时同排，窄窗口自然换行，不人为保留满宽空白行。低频档案操作收进“更多操作”。参数编辑字段优先两行，表格前留8px间距。
- 来源、版本及职责说明保留可访问入口，默认折叠；实际错误、来源过期、数据不足、示范/讨论稿标记不得作为冗余说明隐藏。以侧栏已明确的页面身份不再重复大标题与项目名。
- 工艺默认本地档案页与后端协作页必须分别验证，不能以其中一套验收替代另一套；布局一致不代表数据来源相同，更不代表正式构建已经切换功能开关。
- 表格外框与内部内容之间留白，内部不加纵线；表头上下、行间、末行横线均为同样的 1px 细线。
- 指标、实际值、单位、备注各归其位；实际值加粗，备注保留。先避免遮挡，再均衡分配空间，必要时局部横向滚动。
- 诊断双看板等宽，左右与中间间隔一致。固定表头，纵向滚动条限于表体，弱化且细窄。
- 选中页签圆角浅底、水蓝顶部强调；悬停同圆角但无顶部强调；仅非零预警 / 告警计数使用实心橙 / 红圆标。
- 红橙绿表达业务状态，不装饰大面积背景；缺失数据不能替代成 0 或正常。

在 `apps/admin-web` 中：

```sh
pnpm run dev --host 127.0.0.1
pnpm run check:ui
pnpm run build
```

开发预览：`http://127.0.0.1:5173/ui-lab.html`（端口以 Vite 实际输出为准）。不需要登录，不读取真实业务数据，不写 localStorage 或 API。默认生产构建入口仍是产品 `index.html`，不会把验收台加入产品导航或生产构建入口。

静态守卫检查共享组件绑定、`--wx-*` 令牌引用及固定图标是否缺失；自测覆盖“漏导入应报错”。它**不证明**视觉正确、图标形状正确、列不重叠或业务结论正确。还必须执行工程补充中的浏览器验收。

## 6. 下一步顺序

按“主产品开发阵地”当前已授权的 MVP 优先级继续，不因本入口的历史计划重新从头实施已完成的闭环。后续字段、流程与计算界面复用既有基线，保留数据来源、缺失 / 真实 0、保存失败和历史版本的明确表达。禁止在 UI 任务中擅自确定阈值、评分公式、权限和自动控制动作。

- 必须随业务修正：内容遮挡、单位或来源不清、状态误导、操作不可达、保存 / 版本反馈不清，以及已确认样式回退。冻结的是共同规则，不是禁止修复问题。
- 可延后：纯装饰调整、尚未用到的组件库扩充、全站历史页面统一迁移及 Figma 建库。不再让这些事项占用本阶段专项精力。
- 新增字段和流程不必重开设计规范；改变品牌、语义色定义、全局布局或关键交互习惯时，再单独确认并记录变更。
- 每个受影响业务增量仍应做相应功能回归、类型检查 / 构建、UI 守卫及实际页面验证；静态守卫不代替视觉验收。本地预览确认与发布授权分开处理。
