# WaterX UI 规范 · Foundations 1.0

版本：1.0 阶段基线\
状态：已确认并进入主产品第一批迁移，作为 Components 与 Page Patterns 的正式基线\
验证案例：首页工作台、工艺诊断分析、管理质量·经济高效

## 1. Brand Mark

### 1.1 注册原稿与产品版本

- 以已提交注册的 `WaterX.png` 为品牌造型母版；`assets/waterx-trademark-original.png` 作为原稿存档，不直接嵌入产品顶部栏。
- 产品使用两套由注册原稿主体精确提取的透明底资产：`assets/waterx-logo-on-light.png` 与 `assets/waterx-logo-on-dark-v2.png`。
- 两套产品资产不得改变 Water 的字形比例、字母间距或橙色 X 的结构。
- 页面不得用普通文字、近似字体或重新绘制图形替代正式 Logo。

### 1.2 颜色与背景

- 浅色背景使用原色版：深蓝 Water + 原橙色 X + 透明背景。
- 深色背景使用反白版：浅冰蓝 Water（`#E8F7FF`）+ 原橙色 X + 透明背景。
- 橙色 X 是两套版本中的固定品牌锚点，不因背景切换而改变颜色。
- 深色顶部栏、左侧导航等场景不得再为 Logo 添加白色底板、外框、圆角或阴影。
- 除上述两套官方版本外，设计与开发不得自行生成纯白、单色、渐变或其他换色版本。

### 1.3 尺寸与留白

- 产品桌面顶部栏建议显示尺寸约为 82 × 18px；视觉字高约比 16px 平台名称高 10%，使用透明背景。
- Logo 必须等比例缩放，禁止拉伸、压缩、旋转、描边、加阴影或拆分使用。
- Logo 与平台名称、按钮、边框之间必须保留清晰留白，不得贴合。
- 平台名称建议使用 16px / 700，并以弱分隔线与 Logo 保持约 15px 间距。
- 注册原稿的大面积画布留白与右下角水印不属于产品资产；产品版本只保留商标主体。

## 2. 设计原则

WaterX 的基础设计方向为：专业、克制、清晰、可信。

- 以数据为中心，以业务任务为主线，不以装饰为主线。
- 默认采用适中信息密度；复杂业务页优先保证可观察、可比较、可操作。
- 普通业务页面保持扁平、安静、低噪声；驾驶舱和可视化页面可单独使用增强模式。
- 蓝、白、黑灰构成主要界面颜色；绿、橙、红只承担状态与风险提示。
- 不依赖颜色单独传达状态，颜色必须与数字、文字或形状同时出现。
- 页面已有清晰导航时，不重复展示占空间的页面标题、解释文字和版本标签。

- 同一页面的状态图例只出现一次。
- 分类页签只提示预警和告警；数量为 0 时不显示，正常数量不显示。
- 页签异常计数使用 14px 实心圆、白色 8px 数字，与 12px 页签标题行高协调。
- 区间型状态（如“范围内”）使用状态标签，不使用数值进度条。
- 数值型偏差使用“数值文字 + 3px 进度条”。

## 5. Spacing、Radius、Border、Shadow

### 5.1 间距

基础间距序列：`0 / 2 / 4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64`。

- 桌面页面内边距：24px。
- 1280px 及以下页面内边距：16px。
- 页面主要区块间距：16px。
- 紧凑工具栏内部间距：8–14px。
- 表格单元格左右内边距：7–10px。
- Table Surface 内部四周留白：20px。
- 并列看板桌面左、中、右间距：16px；紧凑断点统一为 8px。

### 5.2 圆角

| 场景 | 圆角 |
|---|---:|
| 小型状态与局部控件 | 4px |
| 输入框、按钮 | 6px |
| 卡片、面板 | 8px |
| 大型浮层 | 12px |
| 状态标签 | 999px |

### 5.3 边框与阴影

- 默认边框：1px `#D4E0E6`。
- 弱分隔线：1px `#E8F0F4`。
- 普通业务卡片默认无明显阴影。
- 仅浮层、固定工具或需要表达层级的元素使用弱阴影。
- 不为每一组内容增加外框；只有独立业务对象或明确操作单元才使用卡片。

## 6. Layout 与导航

### 6.1 全局骨架

| 项目 | 规格 |
|---|---:|
| 顶部栏高度 | 56px |
| 左侧导航展开 | 192px |
| 1280px 以下导航展开 | 180px |
| 左侧导航折叠 | 56px |
| 内容区最大宽度 | 约 1540–1580px |
| 页面栅格 | 12 列思想，业务区可按任务组合 |

### 6.2 左侧导航

- 使用沉稳的深水蓝纯色背景，不使用过浅或漂浮感明显的渐变。
- 一级、二级目录字号一致，层级通过缩进、展开关系、字重和选中背景表达。
- 当前项背景 `#0D6387`，左侧使用 3px 水蓝高亮线。
- 导航纵向滚动条宽度 1px，低透明度，仅悬停时轻微增强；主要用于提示可滚动，不强调拖拽操作。
- 导航应尽量窄，把横向空间留给主工作区。

### 6.3 页面标题与工具栏

- 左侧导航已经明确当前页面时，普通业务页不重复展示大标题、说明和版本标签。
- 首页可以保留必要的运营概览标题和时间切换。
- 筛选栏默认扁平，不增加完整外框和卡片底色。
- 筛选字段靠左；更新、保存紧跟最后一个筛选字段；状态汇总靠右。
- 同组筛选输入框等宽，以完整显示常用内容为最低宽度。
- 筛选框内容居中；更新、保存按钮在紧凑工具栏中使用 72 × 36px。
- 工具栏下方不增加分隔线，与首个 Table Surface 保留 8px 留白。

### 6.4 多看板布局

- 并列看板默认等宽 1:1。
- 看板页签必须与下方表格边界对齐，不悬浮、不跨越两块看板。
- 左侧外间距、看板中间距、右侧外间距必须相等：桌面 16px，紧凑断点 8px。
- 空间足够时内容按比例铺满；只有确实无法完整展示时才出现局部横向滚动。
- 横向滚动内容保持紧凑靠左，不通过大面积留白制造对齐。

## 7. Density

| 类型 | 高度 | 使用条件 |
|---|---:|---|
| 控件 | 36px | 输入框、选择框、普通按钮 |
| 简单表头 | 44px | 单层表头 |
| 简单数据行 | 44px | 单行数据，无附加备注 |
| 分类页签行 | 44px | 数据分类、控制分类 |
| 复杂数据行 | 60px | 实际值备注、数据状态等双层信息 |
| 舒适数据行 | 52px | 需要更强可点击性的中等复杂场景 |

行高必须根据内容层级选择，不允许所有表格统一强行使用一种高度。

## 8. Table 规则

- 常规业务表格放入统一 `Table Surface`：Neutral 0 白色背景、1px Neutral 200 外边框、8px 圆角。
- 表格内容与 Surface 上、左、右、下边框均保留 20px；横向分隔线在 Surface 两侧各留 20px，不与外框相接。
- 表格本体及单元格不设置左右竖线；外层 Surface 负责业务区域边界，表格内部只使用横向分隔线。
- 表头使用 Neutral 25 浅底色，12px / 400，高度 44px，不使用深蓝灰重底色。
- 表头上边线与下边线均使用 1px Neutral 100，颜色、粗细完全一致；两条横线均在 Table Surface 左右各保留 20px。
- 表头上下线、常规行分隔线和最后一行底线统一使用 1px Neutral 100；最后一行底线与 Surface 底边保留 20px，不通过加粗表达结束。
- 列内容不得互相遮挡或重叠。内容能够完整展示时，按业务比例在可用宽度内均衡铺满，不得通过固定超宽首列或空列制造大面积留白。
- 同一表格的表头与表体必须共用一套列宽定义。列宽可根据页签或数据复杂度采用不同变体，不要求所有页签共用同一个最小宽度。
- 只有当前页签或当前页面的内容无法在可用宽度内完整展示时，才设置满足内容安全的最小宽度并启用局部横向滚动；滚动必须局限于表格内容区。
- 表格纵向滚动条宽度 1px、低对比度、透明轨道；悬停时只轻微增强。横向滚动条使用 4–6px，在可操作性与弱化视觉存在感之间取平衡。
- 纵向滚动采用“固定表头 + 独立滚动表体”结构：表头及其上下 1px 横线固定不动；纵向滚动条从表头下方开始，右边缘必须与表头右边缘对齐，不得延伸进入表头区域。
- 单位必须拆分为独立列，不与实际值混排。
- 实际值允许保留一行简短备注；数据状态允许保留一行状态说明。
- 重要实际值加粗，设计值和目标值保持普通层级。
- 必要业务备注可放在表格外下方，不作为数据行或带框表尾；无业务价值、自证性的解释不展示。
- 操作按钮在空间允许时保持单行，不随意换行。
- 配置齿轮放在最后一个业务表头单元格内部并靠右；尺寸约 21px，无底图、无外框。
- 不得为仅存在于表头的齿轮或配置入口单独增加空列；如果确需独立操作列，数据行必须具有对应单元格，保证分隔线完整。
- 表格上方不重复增加无业务价值的标题和解释行。
- 分类页签、简单表头、简单数据行统一 44px；带双层备注的高级业务表使用 60px 行高。

## 9. Progress、Badge 与状态表达

- 定量偏差：文字数值 + 3px 语义色进度条。
- 定性区间：状态标签，如“范围内”。
- 表格附着型分类页签高 44px，标题默认 12px / 400；默认状态不逐项套框。
- Hover：Neutral 25 底色、1px 浅边框、14px 顶部圆角，不使用品牌强调线。
- Selected：Neutral 25 底色、1px 浅水蓝边框、3px Water Blue 500 顶部强调线、14px 顶部圆角，标题 12px / 600；取消页签下边框，使页签与下方表格连续。
- 页签组与 Table Surface 上、左、右边框均保留 20px；选中底色不得贴住 Surface 上边框。
- 此样式仅用于与下方表格直接关联的分类选择；首页时间切换、抽屉 Tabs 等普通页签使用各自组件变体。
- 页签异常计数：14px 实心圆，橙/红底、白色 8px 数字。
- 状态点与进度条必须共用同一套绿、橙、红变量。
- 蓝色进度仅可用于非风险型的信息、品牌或普通完成度，不得与偏差判断混用。
- 红、橙、绿只做点缀性提示，不在大面积背景中滥用。

## 10. Surface 与扁平化原则

- 页面画布使用 Neutral 50，业务内容使用白色表面。
- 优先使用留白、对齐和弱分隔线建立层级。
- 筛选栏、普通标题栏、解释文字区默认不使用卡片外框。
- KPI、独立评分对象、需要明确点击的业务对象可以使用卡片。
- 同一层级避免“卡片里面再套卡片”。
- 阴影不得成为普通业务页的主要层级手段。

## 11. 三类页面的例外与适用方式

### 首页工作台

- 保留“今日运营概览”和时间范围切换。
- KPI、趋势、事项分布和个人任务属于独立对象，可以使用轻卡片。
- 首页的图表蓝色属于信息表达，不视为业务偏差色。

### 工艺诊断分析

- 筛选、操作、状态汇总位于同一行。
- 结果指标与关键控制等宽并列。
- 两块看板的左侧外间距、中间距、右侧外间距必须相等：桌面 16px，紧凑断点 8px。
- 每块看板统一使用 Table Surface，表格内容四周留白 20px，内部横线不得贴外框。
- 分类页签、表头和简单数据行统一 44px。
- 分类标题居中；Hover 使用顶部圆角和浅边框；选中项加粗，使用 Neutral 25 底色、浅水蓝边框和 3px 水蓝顶部强调线，只显示预警、告警数量。

### 经济高效

- 评分对象可以使用必要卡片，但评分区外围不再增加额外卡片框。
- 指标表不重复显示解释性标题行。
- 指标表统一使用 Table Surface：1px Neutral 200 外框、8px 圆角、内部四周 20px 留白，表格本体无左右竖线。
- 表头 44px，复杂数据行 60px。
- 单位、实际值备注和数据状态说明必须保留。
- 得分偏差进度统一使用绿、橙、红。
- 纵向滚动条使用 1px 弱样式；操作列三个按钮在空间允许时保持同一行。

## 12. Codex / 开发约束

1. 新增页面必须优先复用本文 Token，不得在页面内随意新增近似色、近似间距和近似行高。
2. 业务偏差不得使用蓝色代替绿、橙、红。
3. 不得为普通筛选区、解释行和标题行默认增加卡片外框。
4. 常规业务表格必须复用 Table Surface：20px 内留白、无表格左右竖线、所有横向分隔线统一 1px Neutral 100，并保留 20px 底部留白。
5. 并列看板必须等宽，左侧外间距、中间距、右侧外间距使用同一响应式 Token。
6. 表格默认铺满容器；设置最小宽度前必须确认内容在常用 1440px 工作窗口确实无法容纳。
7. 页面状态图例只保留一处。
8. 单位、实际值备注、数据状态说明不得为了压缩宽度被删除。
9. 左侧导航一级、二级目录字号必须一致。
10. 普通业务页不得展示“Foundations”“DEMO”“版本预览”等设计过程标签。
11. 新组件进入开发前必须覆盖 Default、Hover、Focus、Disabled，以及适用的 Selected、Loading、Error 状态。
12. 所有修改必须同时在首页、复杂数据页和高级表格页三个基准案例中回归检查。
