# 人员实体与工作卡片 · 本地示例

本轮只修改精细化原型，没有接入主产品、真实人员、定位、考勤或工单服务，也没有发送任何实际消息。

## 场景和操作

- 延用 `docs/人员权限/角色权限管理_V0.2/model.mjs` 的 9 类岗位定义：运行工、维修工、化验员、安全员、工艺经理、安全经理、生产负责人、厂长，另列系统管理员。经理层/管理层每岗位一人；执行层运行工四人，其余一人；一人一个岗位。
- 12 个示例身份，11 个现场实体，另一个远程系统管理员没有位置，不在场景中虚构落点。这是岗位覆盖示例，不是十万吨水厂的实际定员方案或真实名册。
- 点击姓名或实体，右侧默认打开待办。提供任务状态、截止时间、关联对象与折叠说明；岗位、班次、打卡放在“人员资料”，最近完成放在“已完成”。
- 右卡顶部“人员”打开完整名册；设施台账提供“此处人员”，点选可定位。姓名在头顶附近，拥挤/被浮卡遮挡时隐藏，放大或从名册定位后查看。
- “派发工单 / 下达指令”只需填写名称、对象、截止时间和说明，保存后进入对应人员待接单列表。没有模拟接单等多余操作，也不把保存视为实际发送、接单、完工或验收。
- 新派单保存在当前浏览器 `waterx-twin-personnel-v1` 中；刷新保留。读取异常时提示并禁止覆盖旧数据；写入失败不添加任务。不影响既有巡检记录。

## 后续连接真实人员时的对应关系

1. 以水厂 ID＋稳定人员 ID 对应自然人员档案；岗位来自有效任职，不用显示姓名匹配任务。示例 `PERSON-* / EMP_*` 不能直接当作生产账号。
2. 人员位置单独接入：人员 ID、坐标、所在楼层/区域、采集时间、定位来源、精度/质量。完成现场坐标和模型坐标的标定，再更新实体和头顶标签；室内无可靠位置时仅显示区域，不凭任务地址冒充实际位置。超时显示最后已知位置和时间，断连/未知不造新位置。
3. 工单按指定执行人/复核人关联，区分“本人待办”和“负责范围内查看的事项”；用后台权限及任职、厂区范围校验派发操作。厂长与系统管理员不因打开该演示而自动取得实际派单或审核权。
4. 正式工作状态建议使用“待接单—进行中—待复核—已完成”，逾期为附加标记；复核人与执行人按业务规则分离。当前只是既有任务的状态展示和本地派单，未实现这条后台流程。
5. 指令为发给人员的作业要求，设备控制另行隔离；涉及检修、有限空间等作业，仍需正式审批与现场确认。

定位、考勤与任务采用独立来源；接入后由授权角色查看，不能因数字孪生呈现而放宽原权限。
