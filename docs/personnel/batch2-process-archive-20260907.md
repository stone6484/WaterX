# 第二批：工艺参数—确认日数据—分析日报版本闭环

日期：2026-09-07；状态：本地隔离验证通过。首批历史证据保持原样，见 [首批整合记录](batch1-integration-20260907.md)。

## 当前MVP范围

用户明确：MVP只围绕工艺管理相关必须具备的内容设计开发；安全管理已有成果可做必要优化；其他规划模块暂停。本批没有扩展设备、化验、独立生产运行或其他专业工单。方案范围说明位于设计工作区 `docs/人员权限/MVP阶段范围与工艺闭环_20260907.md`。

三层职责继续为执行人员、专业经理、管理层。专业经理办理日常参数、日数据审核和分析；管理层以查询为主，不默认参与每份日数据、日常参数和日报的审批。

## 业务与权限

- 每条工艺线一个设计参考档案、一个运行目标档案，均有草稿、发布版本、依据、原因及生效起止日期。版本匹配依据业务日期，而非今天或浏览器当前编辑内容。
- 多个已发布版本覆盖同一业务日期时取最新覆盖版本；最新覆盖版本停用则阻止新分析；未来日期的发布不替换过去日期的适用版本。
- 授权专业经理可发布日常调整；标记重大边界变更时可保存草稿，但必要批准权限尚未配置，发布请求被拒绝。没有把厂长职务当作自动批准授权。
- 日数据未确认或存在办理中的更正候选，禁止生成/保存新分析。已保存历史日报始终保留，来源变化显示提示；更正候选终止后有办理历史核查提示。
- 生成结果由后端按PM-0.1.1规则计算，客户端不能提交任意结果。每份结果冻结确认日数据、设计参考、运行目标、模板和规则版本；保存前再次核查全部来源。
- 保存分析日报只允许生成草稿的自然员工，其他账号不能代存；已保存内容不可再写。草稿仅专业人员可见，管理层查看已保存版。导出另行鉴权。
- 所有操作复用首批的有效人员、厂、工艺线及同一笔授权范围检查，不能把其他厂或其他工艺线的权限拼接使用。
- 不自动导入浏览器旧档案，不用样例值补足来源。真实0、缺失、异常、不适用及未配置计算模型保留各自状态。

## 实现位置

- `backend/src/main/resources/db/migration/V21__process_parameters_and_reports.sql`：参数、版本、办理事件、日报来源及结果快照。仅向现有工艺经理角色映射必要参数和报告操作；不创建真实人员授权或业务参数。
- `backend/src/main/java/com/waterx/safety/process/ProcessArchiveService.java`、`ProcessArchiveController.java`：参数发布、日期匹配、分析生成、保存重检、历史读取及导出。
- `ProcessCalculator.java`与`backend/src/main/resources/process-formula-descriptions.json`：迁移现有36项已配置公式到后端；其余模型维持待配置。
- `DailyDataService.java`：仅开放同包内部的6个现有校验/读取方法供新服务复用，原日数据状态流不变。
- `apps/admin-web/src/modules/process-management/ProcessArchivePage.vue`：复用参数编辑器和诊断看板；支持版本查询、来源说明、只读日报及未保存保护。
- `DiagnosisBoards.vue`：增加可选的配置入口显示开关，默认行为不变；快照看板不展示无效配置入口。
- `App.vue`、`packages/api-client/src/index.ts`：必要页面接入和请求/数据类型；保留主产品首批补入的日数据离开、退出、切厂保护。
