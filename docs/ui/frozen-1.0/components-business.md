# WaterX UI 规范 · Components 1.0 第二批

状态：已确认，纳入 Components 1.0 正式基线\
依赖：WaterX Foundations 1.0、Components 1.0 第一批\
覆盖组件：KPI / Metric Card、Card / Content Surface、Form、Modal、Drawer\
验证来源：首页工作台、管理质量·经济高效

## 1. 总体原则

- 组件优先服务数据判断和业务任务，不增加无业务意义的装饰。
- 只有独立业务对象、比较单元或可点击任务才使用完整 Card。
- 同一对象内的信息分组优先使用留白和横向分隔线，避免 Card 嵌套。
- Modal 只处理短确认或少量输入；需要上下文、页签或连续操作时使用 Drawer。
- 表单错误应在字段附近明确呈现，不能只依赖颜色或只在提交后给出顶部提示。

## 2. KPI / Metric Card

### 2.1 规格

| 项目 | 规格 |
|---|---:|
| 标准高度 | 112px |
| 内边距 | 16px |
| 外框 / 圆角 | 1px Neutral 200 / 8px |
| 标签 | 12px / 400 |
| 主值 | 26px / 600 |
| 单位 | 12px / 400 |
| 辅助变化 | 11px / 400 |
| 可选进度 | 3px |

### 2.2 使用规则

- KPI 必须能支持快速扫描、横向比较或异常发现；普通详情字段不得 KPI 化。
- 主值和单位必须分层，单位不与主数字使用同等字重。
- 进度条仅在目标完成度、评分或量化程度有明确含义时使用。
- 业务风险进度使用绿、橙、红；普通趋势或完成度可以使用品牌蓝。
- 可点击 KPI 必须提供 Hover、Focus、Selected 状态；静态 KPI 不制造虚假点击感。
- Selected 使用 Neutral 25 背景、浅水蓝边框和 3px 顶部强调线，不使用大面积品牌色。

## 3. Card / Content Surface

### 3.1 规格

- 外框：1px Neutral 200。
- 圆角：8px。
- 背景：Neutral 0。
- 可选表头：44px，Neutral 25 背景，左右 16px 内边距。
- 正文内边距：16–20px。
- 普通业务 Card 默认无阴影；悬浮层级不通过阴影模拟。

### 3.2 判断标准

满足以下任一条件才使用完整 Card：

1. 内容是独立可识别的业务对象。
2. 内容需要与同级对象横向比较。
3. 整体可点击并进入同一详情或任务。
4. 图表、评分对象等需要稳定边界。

以下内容不单独使用 Card：解释文字、普通筛选行、同一对象内的字段分组、单纯为了对齐而增加的容器。

## 4. Form

### 4.1 布局

- 工具栏筛选继续使用横向紧凑布局。
- 抽屉、弹窗和独立编辑页使用“标签在上、控件在下”的纵向字段。
- 常规桌面表单可使用两列布局，列间距 16px；长文本、复杂选择与关键说明跨两列。
- 字段标签 12px / 500；辅助或错误说明 10–11px。
- 输入、选择控件高度 36px；多行文本最小高度 84px。
- 同组字段纵横间距均为 16px。

### 4.2 状态

- Default：Neutral 200 边框，白色背景。
- Hover：Neutral 300 边框。
- Focus：Water Blue 600 边框和低透明度 2px Focus Ring。
- Error：Danger 边框，并在字段下显示可读错误文字。
- Disabled：Neutral 25 背景、Neutral 100 边框、Neutral 400 文字。
- 必填标识使用红色星号，但错误状态必须同时包含文字说明。

### 4.3 操作

- 表单操作区默认右对齐，次操作在左、主操作在右。
- 常规操作按钮最小宽度 72px、高度 36px。
- 保存草稿使用普通主按钮；删除、清空等不可恢复操作使用 Danger 按钮并二次确认。

## 5. Modal

### 5.1 适用场景

- 单一确认：删除、覆盖、提交、终止。
- 少量且能够一次完成的输入。
- 需要用户明确做出一个决定后才能继续。

### 5.2 规格与行为

- 标准宽度 480px；复杂确认可使用 520px，但不得承担长流程。
- 圆角 12px，使用浮层阴影；遮罩使用低透明度深水蓝黑并轻度模糊背景。
- 标题 18px / 600；正文 12px；头部左右 22px，底部操作区高约 60px。
- 按钮顺序为“取消 → 主操作”；危险操作使用红色按钮。
- 必须支持关闭按钮、Esc 和点击遮罩关闭；正在提交或可能丢失已编辑内容时，应禁用直接关闭并给出说明。
- 禁止在 Modal 中放入多层 Tabs、长表单或连续业务流程。

## 6. Drawer

### 6.1 适用场景

- 查看指标详情、评分标准、结果解读和数据事实。
- 在保留当前列表或看板上下文时完成连续操作。
- 需要页签、多个内容区或较长表单的业务任务。

### 6.2 规格与行为

- 桌面标准宽度 680px，最大宽度为视口的 94%。
- 结构顺序：Header → 普通 Tabs → 可滚动 Body → 固定 Footer。
- Header 最小高度 104px；普通 Tabs 高度 34px；Body 内边距 16px。
- Drawer 内部滚动条使用 1px 弱样式。
- Drawer 正文默认使用一个内容 Surface，内部通过留白和横向分隔线组织；不得把每个段落分别包装成 Card。
- Footer 左侧可显示来源或状态，右侧放置“次操作 → 主操作”。
- 必须支持关闭按钮、Esc 和点击遮罩关闭。
- Drawer 内不得再打开第二层 Drawer；需要更深层编辑时切换内容或进入独立页面。
- Drawer Tabs 属于普通业务 Tabs，不套用表格附着型分类页签的顶部强调样式。

## 7. 开发验收清单

- [ ] KPI 只用于真正需要快速扫描和比较的数据。
- [ ] 静态 KPI 不显示虚假 Hover 或指针反馈。
- [ ] Card 与内部 Flat Group 的层级清楚，没有 Card 套 Card。
- [ ] 表单标签、辅助说明、必填和错误状态完整。
- [ ] 错误状态包含可读文字，不只改变边框颜色。
- [ ] Modal 只承载短确认或少量输入。
- [ ] Drawer 保留原页面上下文，Header、Body、Footer 层级稳定。
- [ ] Modal 与 Drawer 支持键盘 Esc、关闭按钮及焦点可见。
- [ ] Drawer 没有嵌套 Drawer，普通 Tabs 未误用表格附着型页签样式。
- [ ] 首页与经济高效案例完成回归检查。

## 8. 确认后的执行结果

1. KPI 与 Card 基线已同步到首页工作台；静态 KPI 不再显示虚假 Hover。
2. 评分卡与 Drawer 基线已同步到经济高效；选中使用品牌蓝，业务预警保留在进度与状态中。
3. Form 与 Modal 已在“发起改进”组件案例中完成交互验证。
4. 第二批已并入 Components 1.0 基线，下一步进入 Page Patterns 1.0。
