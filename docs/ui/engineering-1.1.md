# WaterX UI 工程补充候选 1.1

日期：2026-09-05。继承 1.0 已确认视觉。本文补“如何正确表达与验证”，不改工艺规则、不发布新的全站主题。

## 1. 先确定页面要完成的任务

| 任务 | 优先模式 | 不应混入的内容 |
| --- | --- | --- |
| 查看当日运行与待办 | 运营工作台 | 无来源的演示 KPI、重复告警汇总 |
| 对照目标发现偏差 | 诊断双看板 | 把设计值当本次目标、以缺失值推算正常 |
| 查看指标得分及证据 | 指标评价表 | 把数据完整度当运行得分 |
| 检查条目并记录事实 | 主从详情 | 全部信息塞进一个超宽列表 |
| 填报 / 编辑 / 提交 | 表单或现有抽屉 | 没有结果反馈的保存按钮 |

优先复用已有页面模式，不因为新模块就另造颜色、表头、状态标签和筛选框。

## 2. 数据可信表达

数据质量与业务结果是两个维度。UI 呈现业务层给定的结论，不独立发明阈值；下表是表达要求，不是新增评分算法。

| 输入情况 | 实际值显示 | 结果 / 备注 | 禁止 |
| --- | --- | --- | --- |
| 有效数值 | 原精度规范下的数值，单位独立 | 依据适用业务规则显示结论 | 仅因有数值就显示正常 |
| 真实记录为 0 | `0` | 保留来源，业务规则继续判断 | `value || '—'` 把零吞掉 |
| 没有数据 | `—` | 数据缺失 / 数据不足，必要时说明缺什么 | 用 0、设计值或演示值补齐并判正常 |
| 低于检出限 | 如 `<0.02` | 保留限定符与检出限来源 | 去掉 `<` 或替换成 0；UI 自行决定替代值 |
| 历史值 / 当前未更新 | 原数值与采样时间 | 标明历史 / 尚未更新 | 冒充所选日期实时值 |
| 目标缺失或不适用 | 有效实际值仍显示 | 偏差 `—`，说明目标缺失或不适用 | 除以 0，或生成绿色 0% 偏差 |
| 读取失败 | 当前读取失败状态 | 明确未形成本次结论；若保留旧值必须标时间 | 一边报错一边显示新鲜的正常结论 |

有效值与业务结论不得混作一列。复合指标可保留已批准格式，但其多个值 / 单位必须能一一对应；不得为了列宽改变指标含义。结果颜色同时服务文本、标识和进度条，同一语义复用已有令牌。

## 3. 表格：可读性优先于消除滚动条

1. 按当前页签的真实内容确定列宽需求，包括最长指标、单位、实际值、状态和操作；不能用全模块最长名称撑宽每个短内容页签。
2. 名称 / 单位 / 数值等关键内容不跨列；说明文字可自然换行。经业务确认可缩写的内容须能取回完整信息，不得靠隐藏文字让验收通过。
3. 能放下时，剩余宽度均衡分给合适的列，不集中给第一列；“均衡”不是把名称、数字、备注机械设成完全相同宽度。
4. 放不下时，表格设内容所需的最小宽度，外层局部横向滚动；不要让整个页面滚动，也不要缩小到难以阅读。
5. 固定表头和表体共享列宽来源。纵向滚动只作用于表体，上下表头线不移动；滚动条不穿过表头。
6. 表头 / 行间 / 末行都用 `--wx-border-subtle`，外框用 `--wx-border-default`。不额外加粗结束线。
7. 本轮验收台的压力样例不是新业务表格组件；主产品双表头 / 表体结构仍沿用现有诊断、管理质量实现。

验收不能只判断 `td` 是否相交：单元格边界本来就不相交，溢出的**文字**仍可能覆盖下一列。应同时检查可见文字边界、换行和横向滚动后最右列是否完整。

## 4. 字段与操作的状态契约

- 输入有明确标签；必填标记不代替校验。错误文字紧贴字段，不能只有红框。
- `WxField` 默认仍是横向布局，兼容旧调用。新编辑表单可用 `layout="stacked"`；业务校验由调用方提供 `error`。
- 新调用用作用域插槽绑定 `controlProps`，自动关联字段 ID、必填、错误状态与说明。旧插槽可继续使用，但不会自动获得这些属性，不能宣称全站已完成关联。
- `WxButton` 的 `loading` 同时禁用操作并标示忙碌；所有按钮变体禁用时均使用中性样式。业务提交还需在处理函数 / 请求层阻止重复，不把按钮灰掉等同于服务端幂等。
- 保存成功、失败、未提交修改由业务请求结果决定；加载动画结束不代表成功。验收台模拟保存必须明确不产生记录。
- 加载 / 空数据 / 失败 / 无权限分别表达，保持用户的筛选上下文；只有真实可执行的恢复动作才显示按钮。
- 键盘焦点可见，错误关联可读。后续批次已在管理质量详情中接入 `WxDialog`，支持 Esc、焦点循环及关闭返回；编辑脏数据保护、复杂危险确认仍未统一，不标成完成。见 [登录与抽屉补充](login-and-drawer-1.1.md)。

示例：

```vue
<WxField v-slot="{ controlProps }" label="实测值" layout="stacked"
  required :error="error" help="缺失与 0 是不同状态">
  <WxInput v-model="value" v-bind="controlProps" />
</WxField>
```

## 5. 每批修改的完成门槛

| 检查 | 最小通过条件 |
| --- | --- |
| 代码连通 | `check:ui`、类型检查 / 构建、`git diff --check` 通过；静态结果不能替代浏览器 |
| 基线宽度 | 1440×900 下页面无整体横向溢出；再用窄容器 / 长内容验证降级 |
| 表格 | 短内容无不必要横滚；长内容不跨列；表头表体对齐；最右列可达；滚动时表头及两条线固定 |
| 表达 | 测试真实 0、缺失、长单位、历史值；不把这些状态都渲染成正常 |
| 表单 | 空值 / 非法值出错，有效 0 不被吞掉；错误说明与控件关联；处理中不能重复点击 |
| 组件 | 默认、悬停、键盘焦点、禁用、加载样例完整；控制台无新增错误 |
| 兼容 | 改共享 CSS 时复查已使用它的页面；未实测的模块必须注明，不以验收台通过代替全站通过 |
| 交接 | 更新规范入口与 HANDOFF；分别写明本地、GitHub、部署状态 |

任何视觉候选先本地预览；关键业务规则或权限变化应单独提出，不藏在 UI 调整里。
