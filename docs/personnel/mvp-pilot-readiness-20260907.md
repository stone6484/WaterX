## 发布前必须明确

|---|---|---|

| 首批项目和人员 | 未配置真实人员；维护结构变更暂缓 | 项目、工艺线、本人账号、执行人、专业审核人、只读管理者及有效期明确。授权维护或批准的受控维护方式能实际完成停用、改派和撤销并留痕。角色名不能代替逐项有效授权。 |
| 旧角色权限与其他安全入口 | 本轮仅收紧检查/隐患核心 | 旧PLANT_MANAGER等角色可能在其他安全子模块具有既有权限，不能把本轮只读结论外推到全站；试点前核定实际允许入口及后端操作范围，不能只隐藏按钮。 |

| 必要审批 | 日常职责已分离；重大变更禁止发布 | 初期不使用尚未配置的重大变更批准功能；若试点必须使用，再单独明确批准职责和记录依据。无设备控制、自动指令或危险作业上线承诺。 |
| 发布与接收安排 | 未执行 | 确认待发布改动/版本、发布窗口、接收负责人和失败恢复点；注意已有自动部署，推送本身可能触发升级，因此不能先推送再考虑数据库隔离。 |

## 部署后、交给真实人员前再走一遍

1. 在最终入口，用分别授权的本人账号登录；确认不是管理员代办，不依赖旧浏览器缓存或示范档案。
2. 实际走通工艺设计/目标→分派日数据→本人填报→退回/重提/确认→偏差分析→同源日报及更正保留旧版。
3. 实际走通安全检查/上报→专业派发→本人接收整改→手机证据/确认→独立复查/退回→归档下载。
4. 检查跨厂/跨线、他人记录、自审、失效授权、重复提交与旧版本覆盖均被拦截；核对试点角色的其他旧入口不能越权。
5. 退出重登、刷新/中断恢复、附件下载与试点实际使用的打印/导出格式验证；明确问题记录入口和接收人。

模拟人员验证的是功能与权限规则，不能证明真实员工授权正确、参数正确或线上数据可恢复。达到发布前置条件时通知用户确认发布；发布后最终入口通过上述验证，才宣布可以交给真实试点人员使用。

## 暂不追求

不为首批试点扩展其他规划模块、自动采集、工艺操作指导、设备控制、全模型校准或全站复杂审批。危险作业和其他未验收安全能力不可被本次核心流程通过一并带上“已验收”标签。
