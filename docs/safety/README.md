## 必须保持的业务规则

1. 上报只需实际位置、现象、发现时间，可补临时措施与附件。分类、等级、责任、期限、预计费用不自动代填。费用未知留空，明确零元保留0。
2. 安全管理人或厂级负责人按当前厂区的有效业务角色受理、分派及复查；技术平台管理员权限本身不等于安全业务签批资格。执行检查、接收、整改必须是实际指派员工本人。部门、员工、风险关联都要校验同厂区。
3. 新流程：待受理 → 待接收 → 整改中 → 待复查 → 已归档。退回接收回到待受理；复查不通过回到整改中。过期是附加属性，不覆盖业务状态。
4. 整改人不能验收本人整改，即使其同时具有安全管理角色；每轮退回后须有本轮整改证据，旧照片不能直接满足下一轮提交。关闭后原记录与附件不覆盖。历史操作保存当时内容、人员、时间及证据索引。
5. 检查逐项填真实结论；不适用须依据；条件项不涉及时关联子项不适用；“有无其他隐患”等反向问题按“是”形成待受理问题。切换不适用后不残留原问题、旧回答或隐患链接。重复提交不重复生成任务/隐患。
6. 检查可关联可见且未关闭的同一隐患，增加发现来源；已关闭问题再次出现形成新记录，不伪造原始发现时间。综合记录单本批采用开放记录项；多处独立问题可分别现场上报，尚无动态多行问题录入。
7. 发布模板修订产生新版本；历史任务保留创建时的内容。升级前任务只能标为升级时捕获，不宣称恢复了真实的原始签署版本。周期暂停/恢复留理由，恢复时不将暂停期补记为完成。
8. 草稿按账号、厂区、记录隔离；关闭前可保存/放弃，切换页面暂存文字。附件与签字不进草稿，提交时重新确认。过期隐患草稿不覆盖更新后的版本。
